# AGENTS.md

**Scope**: single-machine deployment (2026-11-14). Department isolation + optional document ACL are the supported permission model; multi-tenancy, per-tenant quotas and billing are out of scope (`OPTIMIZATION_PLAN.md` §11.1.2/§11.2.2).

## Core Architecture
- **Chat flow**: `src/chat_service.py` owns validation, maintenance gating, answer caching, error classification and metrics for both `/chat` and `/chat/stream`; `main.py` only adapts to HTTP. Request/response models live in `src/schemas.py`. `/chat` uses the sync graph node; `/chat/stream` uses an async node (`src/agent.py`: `call_model_async` / `app_async`, `llm.ainvoke`). The stream runs the graph in a producer `asyncio` task and forwards frames from a queue — Starlette cancels streaming responses via an anyio cancel scope, and cancellation thrown at a generator's `yield` does not reach a graph nested inside another async generator, so `_astream` explicitly cancels the producer instead. A cancelled turn is never cached or persisted and is counted as `status="cancelled"` plus `agent_rag_chat_cancelled_total{endpoint}` — deliberately not `status="error"`, so user clicks do not trip the error-rate alert. `/chat` runs in a threadpool, so its in-flight call cannot be interrupted.
- **RAG Pipeline**: LangGraph $\rightarrow$ Milvus $\rightarrow$ Cross-Encoder Reranker. Answers return `sources` (`source`+`page`) built from retrieval metadata; excerpts are wrapped in `<document>` tags and treated as untrusted data.
- **Ingestion**: multi-format (`pdf/docx/pptx/xlsx/csv/md/txt/html/json`) via `src/loaders.py`; XLSX/CSV are split into header-repeating row blocks (`XLSX_ROWS_PER_CHUNK`/`CSV_ROWS_PER_CHUNK`, `XLSX_MAX_ROWS`); optional PDF table extraction (`PDF_TABLES_ENABLED`, needs pdfplumber) and OCR (`OCR_ENABLED`, needs pytesseract/pdf2image); keep metadata keys stable or the Milvus schema requires a reset; PDF text comes from pypdfium2 (pdfium, 10-20x faster than pypdf) with a pypdf fallback, and the resolved parser is folded into the chunk signature so switching it re-chunks; chunking is token-aware (`CHUNK_TOKENS`/`CHUNK_OVERLAP_TOKENS`, Chinese punctuation, optional title prefix; configurable from the 分片 card); `EMBEDDING_BATCH_SIZE` tunes local embedding throughput and each file logs parse/chunk/embed/write timings; `INGEST_PREFETCH` (default off, depth `INGEST_PREFETCH_DEPTH` 1–8) parses/chunks the next changed document on a worker thread while the main thread embeds and writes the current one — all vector-store access stays on the main thread, so stats, skip detection and the shadow rebuild are unchanged; incremental — chunks carry `dept/source/page|slide|sheet/doc_id/doc_hash/kind/chunk_index`; `doc_hash` folds the effective chunking/parser signature, so unchanged files are skipped while a parameter change re-chunks them; changed files are written first and old versions deleted afterwards (crash-safe), removed ones pruned. `POST /admin/api/jobs/{id}/cancel` stops at a document boundary, never between writing new chunks and deleting the old version; `POST /admin/api/ingest/estimate` and `IngestRequest.dry_run` report the cost without writing (a dry run parses/chunks/embeds only the first N changed documents).
- **Zero-downtime rebuild**: `--reset` / the admin console build into a shadow index (Milvus: temp collection + alias swap; FAISS: temp dir + `os.replace`). Queries keep hitting the live index; maintenance is only set during the millisecond alias swap. `count()` is the write target, `live_count()` is what queries see.
- **Citations**: answers include `sources` (`source` + `page`/`slide`/`sheet` + `kind` + `snippet` + relative `score`); same-page chunks are merged, and `score` is a rank (1.0 for the top hit), not a cross-engine comparable value. Clicking a citation calls `GET /sources/content` (`src/sources_api.py`), which resolves `source` + location through `kb_engine.fetch_source_chunks` (dept filter inside the store, then ACL) and returns the full chunk text; the UI renders it as plain text in a modal. `GET /sources/file` serves the original upload (inline or `download=1`) after the same dept + ACL check and a `DATA_DIR` path-escape guard. Responses also carry a 1-based `citations` map; the UI turns `[n]` in the answer into clickable anchors.
- **Failure fallback**: when the LLM is unreachable/timeouts *after* retrieval, the graph answers with the top excerpts (`degraded=true`, `degraded_reason=llm_unavailable`); degraded answers are never cached. Toggle with `LLM_FALLBACK_ENABLED`.
- **CORS**: `CORS_ORIGINS` (comma-separated) enables CORS for the public endpoints; the admin API also rejects foreign `Origin` headers.
- **TLS edge**: the production stack puts Caddy (internal CA, hostname `KB_SITE_ADDRESS`, default `kb.internal`) in front; the app is published on `127.0.0.1` only, so login/chat never travel in cleartext. `config/Caddyfile` overwrites `X-Forwarded-For` with the real hop (otherwise a caller could spoof it to dodge per-IP limits), but Docker's port forwarding still makes every client look like the gateway IP (e.g. `172.25.0.1`), so per-IP rate limits and audit IPs share one bucket — fine for a small LAN. Host `:80` is left to macOS Apache; only `:443` is published. `volumes-prod/caddy` is not in `make backup` (losing it just re-issues the root cert).
- **Authentication**: `AUTH_MODE=none` (default, body-supplied identity) or `jwt` (`src/auth.py`; bearer token is the only source of user/depts/groups, body identity ignored, admin claim gates `/admin/api`). Tokens are minted with `scripts/mint_token.py`; a weak secret refuses startup. Three ways to obtain one: local accounts (`AUTH_LOCAL_LOGIN_ENABLED` + `POST /auth/login`, `src/local_auth.py` — scrypt hashes in `AUTH_USERS_FILE`, `scripts/manage_users.py` or the console's 账号 card; the token carries a `ver` claim so disabling an account or changing its password revokes outstanding tokens), an OIDC browser flow (`AUTH_OIDC_*`: `/auth/login` → `/auth/callback` → `/admin#token=...`), or an external issuer. OIDC/JWKS verification: `AUTH_JWKS_URL`/`AUTH_JWKS_FILE` with claim mapping via `AUTH_CLAIM_*`/`AUTH_ADMIN_ROLE`/`AUTH_ROLE_DEPT_PREFIX`/`AUTH_DENY_ROLE`/`AUTH_DEFAULT_DEPTS`; `python scripts/check_oidc.py --self-test` verifies the chain offline and `--issuer/--jwks` probes a real provider. `GET /admin/api/session` tells the console its auth mode and claims while `/info` exposes `auth_mode`/`oidc_login`/`local_login`; both UIs (`/admin`, `/ui/`) have a login gate. Department/ACL logic sits behind this, so tests can use either mode.
- **Licensing / delivery (private deployments)**: `LICENSE_ENABLED=false` by default. `src/license.py` verifies an Ed25519-signed `config/license.json` (payload + base64 signature, canonical JSON; public key compiled in, private key never ships) and reports `disabled/valid/grace/expired/missing/invalid` via `/info.license` and `GET /admin/api/license`. A missing/forged license refuses startup (fail closed); an expired one keeps chat/citations/sessions working and a middleware blocks only `POST/PUT/PATCH/DELETE /admin/api/*` with 403 `license_expired` after `LICENSE_GRACE_DAYS` (14) — never take the KB offline over a renewal. Licenses carry `licensee/edition/expires_at/max_depts/max_docs/features`; `scripts/doctor.py` surfaces them (limits are informational, not enforced). Vendor flow: `make license-init` (writes `config/license_private.pem`, 0600, gitignored), then `make license-console` (`scripts/license_console.py`: loopback-only web UI with a per-process token, signs into `licenses/` and re-verifies files) or headless `python scripts/issue_license.py --licensee "ACME" --days 365 [--depts N --docs N --features a,b]`; `--trial` issues a 30-day evaluation license (1 dept/5k docs, hard cap 90 days, console has a one-click preset). `scripts/usage_report.py` (`make usage-report`) renders aggregate usage/value reports (text/markdown/csv/json) from the session DB + audit log + license for billing/QBR; it never includes transcripts or user ids. `docker-compose.demo.yml` + `.env.demo.example` (`make demo-up/demo-seed/demo-down`) run a license-free FAISS demo that mounts only `data/Demo`, disables server-side sessions and rate-limits visitors. The customer installs the file through the admin 许可 card (exempt from the write gate, so renewals work in grace), and the first install must be in place before startup because a missing license is fail-closed. `make package [LICENSE=<file>]` / `scripts/package_release.py` builds `dist/agent-rag-<version>-delivery.tar.gz` (+ `.sha256`) with compose/Dockerfile/src/static/scripts/docs/`.env.example`, generated `INSTALL.md` and `PACKAGE.json` (per-file SHA256); it never includes `data/logs/backups/volumes`, tests, `.env`, `*.pem`, `config/users.json` or rendered Alertmanager secrets. `make package-image` adds `docker save`. This is a contract anchor, not DRM (MIT source).
- **Permission Model**: Department-based isolation implemented via Milvus `expr` metadata filtering (`dept == 'dept_name'`, or `dept in [...]` for multi-department users; FAISS filters after retrieval). Optional document-level ACL lives in `src/acl.py` (`ACL_ENABLED`/`ACL_FILE`, user ids or `group:xxx`), applied after retrieval for both backends. `CHAT_API_KEY` optionally gates `/chat` and `/chat/stream`. Department names are validated/escaped in `src/validation.py` before being embedded in the expression; the API returns 400 for invalid values. The department is injected into tools from `AgentState` (`InjectedState`), never supplied by the LLM.
- **State Management**: Handled by LangGraph `AgentState`, tracking `user_id` and `user_dept` per session.
- **Server-side sessions**: `src/sessions.py` (SQLite at `SESSIONS_DB_PATH`, default `./logs/sessions.db`; `SESSIONS_ENABLED`). `POST /sessions` creates one; `ChatRequest.session_id` makes the server own the transcript and ignores the body `history`, so requests stay a constant size. Sessions are checked against the caller's `user_id`; `/sessions` also lists/reads/deletes. Once a conversation exceeds `2 × HISTORY_MAX_MESSAGES`, older turns are folded into a running summary by `summarize_text` (one extra LLM call per window, `SESSION_SUMMARY_*`); if that call fails the prompt falls back to the last `HISTORY_MAX_MESSAGES`. `logs/` is already mounted and included in `make backup`. `/ui/` lists sessions in a left sidebar (`static/sessions.js`, with search, offset pagination (`GET /sessions?limit&offset`) and loading/error states), sends only `session_id` after the first turn, and rebuilds the transcript from `GET /sessions/{id}` on reload; answers carry numbered citations that open a copyable source preview, a copy/regenerate toolbar, Markdown export and an optional 「调试信息」 toggle for timing chips; deletion uses the themed dialog, and JWT mode shows the token identity and departments instead of editable fields while the theme key is shared with the console; preset questions follow the UI language, long transcripts render the newest 60 messages with a 「显示更早」 break, and Markdown exports include timestamps and citations. `/info` exposes `sessions_enabled`/`history_max_messages` and the page falls back to localStorage when sessions are disabled. Sessions can be renamed (`PATCH /sessions/{id}`), searched server-side by title/summary/message content (`GET /sessions?q=`), and rated per assistant message (`POST/GET /sessions/{id}/feedback`, table `feedback` keyed by session+seq+user); the UI also deep-links via `?session=<id>` and shows recall/rerank details in 「调试信息」.

## Developer Commands
All commands assume the conda env `agent-rag` is active (`conda activate agent-rag`).
Container build: `docker build -t agent-rag:dev .` (CPU-only torch, embedding model baked in; build args `PIP_INDEX_URL`/`TORCH_INDEX_URL`/`HF_ENDPOINT` for slow networks). Production stack: `docker compose -f docker-compose.prod.yml up -d --build` (etcd + Milvus + app + caddy). Only caddy publishes `:443`; the app is bound to `127.0.0.1:8000` and clients use `https://$KB_SITE_ADDRESS` (default `kb.internal`, internal CA — see `DEPLOYMENT_CN.md` §4.1.5). The container healthcheck uses `/info` (liveness) so a fresh deployment is healthy before the first ingestion; point load balancers at `/health` (readiness).
`make help` lists shortcuts (`install/data/ingest/run/test/lint/cov/milvus-up/milvus-down/reset-*/doctor/backup/restore/daily-backup/boot-recover/agents-install/agents-status/agents-uninstall/monitor-config/monitor-up/monitor-down/monitor-check/license-init/license-verify/license-console/package/package-image/check/eval/release/clean/prune`); `scripts/doctor.py` checks the environment, `scripts/check_release.py` verifies that `src/version.py`, `CHANGELOG.md`, the git tag and `APP_TAG` agree (`make release` also runs lint + tests), and `scripts/check_monitoring.py` validates the Prometheus/Grafana configs offline. `scripts/backup.py` archives `data/`, `config/`, `logs/` and the live index with per-file hashes; `scripts/restore.py` verifies the archive and refuses while the API or Milvus/etcd is up.
- **Rate limit / deadline**: `RATE_LIMIT_PER_MINUTE` (0 = off, per forwarded IP or user id, 429 + `Retry-After`); `CHAT_TIMEOUT` caps the whole request (504 `timeout`). Error classification lives in `src/errors.py`.
- **History**: `HISTORY_MAX_MESSAGES` (default 20) is what actually reaches the model; older messages are dropped in user/assistant pairs by `chat_service.trim_history`, so long chats never fail validation. The schema's 200-message cap is only an abuse guard.
- **API Server**: `uvicorn main:app --host 127.0.0.1 --port 8000` (chat UI `/ui/`, ingestion console `/admin`, `GET /info` exposes backend/model)
- **Admin Console**: `/admin` — upload/list/delete files and trigger incremental or full ingestion. The 模型 card edits chat generation at runtime (`GET/PUT/DELETE /admin/api/model`, `POST /admin/api/model/test`); overrides persist to `config/model_settings.json` (0600, gitignored, backed up) and `src/agent.py` rebuilds the bound model on the next turn, while `.env` `LLM_*` stays the default. Responses only expose a masked key hint; ingestion/retrieval keep `EMBEDDING_*`. The 文件与向量 card merges the file list with the live index (`GET /admin/api/vectors`, `/vectors/chunks`, `POST /vectors/search`) and can delete a document's vectors while keeping its file, prune orphans (`DELETE /vectors/{doc_id}`, `POST /vectors/prune`; 409 while ingesting). APIs live under `/admin/api`; loopback-only unless `ADMIN_TOKEN` is set (then send `X-Admin-Token`). Ingestion runs in a background thread; jobs persist to `logs/ingest_jobs.json` and admin actions are audited in `logs/admin_audit.log` (`GET /admin/api/audit`). Uploads are capped per file and per request (`MAX_UPLOAD_TOTAL_MB`). With `AUTH_LOCAL_LOGIN_ENABLED` the console also manages accounts (`/admin/api/users`, the 账号 card); the last enabled admin cannot be demoted, disabled or deleted (409); each row opens an editor for departments/groups/admin/status, and password changes use a themed dialog with confirmation instead of the native prompt (old tokens are revoked). The 分片 card configures the token window, overlap, Chinese punctuation and title prefix at runtime (`/admin/api/chunking`); the effective signature is folded into `doc_hash`, so a parameter change re-chunks indexed documents on the next ingestion (the card can save and start the incremental re-ingest). The 运行监视 card polls `/admin/api/jobs/{id}` and shows processed/total documents, chunks written, elapsed time, throughput, ETA (after 40%), the current file and the live log; the header 入库中 pill jumps to it. 「模型」卡片可运行时修改对话生成（`GET/PUT/DELETE /admin/api/model`、`POST /admin/api/model/test`），覆盖配置持久化到 `config/model_settings.json`（0600、gitignore、进备份），`src/agent.py` 下一轮自动重建模型，`.env` 的 `LLM_*` 仍是默认；响应只回掩码 Key，入库/检索仍用 `EMBEDDING_*`。`/admin` 与 `/ui/` 用共享的 `ragBearer`（localStorage，登录一次后新标签页/重启都保持，任一页登出同时清除；`ADMIN_TOKEN`/`X-API-Key` 不跨页）；控制台左侧有固定分区菜单（分组为内容/配置/运维/危险区，重建索引独立标红，标签页式切换，记住上次分区并切换即刷新（30 秒内优先复用已加载数据），右侧只显示当前分区，隐藏入口不可用，方向键可切换；≤1000px 变为顶部吸附的横向滚动标签栏，右缘渐隐并自动把当前分区滚入视野），菜单显示待入库文件数与账号数；顶栏可切换深色/浅色/自定义主题（配色存 localStorage，主按钮文字按主色亮度选黑/白，自定义弹窗带预设与实时预览，仅作用于管理台），并显示可切换的当前部门、入库中指示、最后刷新时间与折叠的后端/模型/上限，身份/主题/返回/退出收进账户菜单（语言保持一级）；上传与文件列表同卡（卡内可选上传部门），「索引维护」（入库/清理/检索测试）独立分卡；卡片加载时显示角标，表格共用骨架/空态/错误+重试三态；宽表格横向滚动且文件表操作列固定，文件表可点表头排序（支持键盘）并按 50 条分页，审计支持时间/文本筛选、条数切换、本地时间显示、成败徽章与 CSV 导出；重建索引需勾选并输入 `RESET` 二次确认，其他破坏性操作使用统一确认弹窗；刷新后自动恢复未完成的入库任务，浏览器标题跟随当前分区；操作结果除行内提示外还会弹 toast；模型/账号表单使用显式标签，模型改动有未保存提示；账号行提供「编辑」（部门/组/管理员/启停）与「改密码」弹窗（二次确认，改后旧 token 立即失效）；「分片」卡片可运行时配置 token 窗口/重叠、中文标点与标题前缀（`/admin/api/chunking`），生效签名并入 `doc_hash`，改参数后下次入库自动重切（卡片可直接保存并触发增量重切）。「运行监视」卡片轮询 `/admin/api/jobs/{id}`，显示已处理/总文档、已写 chunk、已用时、速度、预计剩余（40% 后）、当前文件与实时日志；顶栏「入库中」可跳转。
- **Local accounts**: `src/local_auth.py` — `hashlib.scrypt` (no extra dependency, ~150 ms/verify), JSON store at `AUTH_USERS_FILE` (gitignored, written atomically, cached by mtime), CLI `python scripts/manage_users.py add|list|show|set|passwd|disable|enable|delete`. `POST /auth/login` accepts JSON or form, is rate limited per IP (`AUTH_LOGIN_RATE_LIMIT`, 429) and audited (`auth.login`). The minted token carries `ver`; `auth.identity_from_headers` rejects it once the account is disabled, deleted or its password/permissions change. Tokens without `ver` (IdP/gateway) are never checked against the file, so both mechanisms coexist.
- **Data Ingestion**: `python run_ingestion.py` (Must be run before API to populate the vector store).
- **LLM Check**: `python scripts/check_llm.py` (probes `/models` + one chat completion before starting the API).
- **Offline Retrieval Check**: `python scripts/verify_retrieval.py` (no LLM needed; asserts dept isolation).
- **Retrieval Eval**: `VECTOR_STORE_TYPE=faiss python scripts/eval_retrieval.py` (hit@k, MRR, leakage from `eval/cases.jsonl`; run for both backends after ingestion). Hybrid retrieval is on by default; compare with `HYBRID_ENABLED=false`.
- **Hybrid Retrieval**: `HYBRID_ENGINE=auto` (default) uses Milvus server-side sparse BM25 when the server is >= 2.5 and the collection has a `sparse` field with a BM25 index; otherwise it falls back to in-process BM25 (`src/lexical.py`, per-department, RRF-fused, warmed in a background thread). `local` forces in-process; `milvus` fails loudly if unsupported. Check `GET /info` → `hybrid.engine`. Unit checks: `python scripts/check_hybrid.py`; server-side end-to-end: `VECTOR_STORE_TYPE=milvus python scripts/check_hybrid_milvus.py` (skips below 2.5, uses a throwaway collection).
- **Metrics**: `GET /metrics` (Prometheus). Optional `METRICS_TOKEN` requires `Authorization: Bearer ...`. Per-process counters; do not expose publicly. `agent_rag_retrieval_engine_total{engine}` shows whether vector/local/milvus/fallback served each query. `agent_rag_backup_age_seconds` / `agent_rag_backup_archives` stat `BACKUP_DIR` on scrape (prod mounts `./backups` read-only at `/app/backups`); `AgentRagBackupStale` fires after 48h without a new archive.
- **Monitoring stack**: `docker-compose.monitoring.yml` adds Prometheus + Alertmanager + blackbox_exporter + Grafana + Loki/Promtail on the external `agent-rag-prod` network (`make monitor-up|monitor-down`); configs live in `monitoring/` (scrape jobs, 7 alert rules, dashboard, datasource provisioning, `loki.yml`/`promtail.yml`) and data in gitignored `volumes-monitoring/`. UIs bind to loopback (`:9090`, `:9093`, `:3000`, `:3100`). `make monitor-check` / `scripts/check_monitoring.py` validates the files offline and fails if a rule or dashboard references an `agent_rag_*` metric missing from `src/metrics.py`. Alert delivery (email/Slack/webhook) is opt-in through `ALERTMANAGER_*` in `.env`: `make monitor-config` / `scripts/render_alertmanager.py` renders the gitignored `monitoring/alertmanager/alertmanager.yml` (no channel → `noop` receiver; 9093 silences). Promtail ships `agent-rag-*` container stdout to Loki (`LOKI_RETENTION`, default 30d) and Grafana queries it through the `loki` datasource/logs panel; it needs `${DOCKER_SOCKET}`/`${DOCKER_CONTAINERS_DIR}` mounts (defaults for Linux; override for rootless/remote daemons, and it can be omitted without losing metrics/alerts).
- **Ops automation (macOS launchd)**: `scripts/install_launchd.py` installs `com.agent-rag.boot-recover` (login: `scripts/boot_recover.py` starts colima if needed, `compose up -d` prod + monitoring, waits for `/info`) and `com.agent-rag.daily-backup` (03:30: `scripts/daily_backup.py` silences `AgentRagHealthDown` for 15 min, pauses the prod stack and any running dev Milvus, archives with `backup.py`, keeps `BACKUP_KEEP`, optionally copies to `OFFSITE_BACKUP_DIR` with a sha256 check, then restarts in `finally`). When `volumes-prod/milvus` exists the archive is forced to Milvus even if the host `.env` says `faiss` (prod compose pins milvus). A backup is ~1 minute of downtime; LaunchAgents run after login, so a reboot needs one login.
- **Hashing / summaries**: file digests go through `src/hashing.py` (cached by `path+mtime+size`); admin listing uses `kb_engine.doc_summary()` (cached for 5s and invalidated on writes), never per-file queries.
- **Caching**: `src/cache.py` is an LRU+TTL FAQ cache keyed by `dept + normalised question`; only single-turn answers with exactly one LLM call are stored, and every KB write clears it. `src/embedding_cache.py` memoises `embed_query` (ingestion embeddings are not cached). Bypass with `Cache-Control: no-cache`. `/health` → `cache`, metrics `agent_rag_cache_total{cache,result}`.
- **Health Check**: `GET /health` (vector store chunks, ingestion job, maintenance, disk headroom; `?probe=1` also pings the LLM). `down` → HTTP 503 when the index is empty/unreachable; `degraded` → 200 during ingestion/rebuild or when a writable directory has less than `HEALTH_MIN_FREE_MB` free (`storage` block names the tightest path). A full disk never fails queries, so this is the only signal that writes are about to break; after freeing space, Milvus still needs `docker restart milvus-standalone` because RocksDB caches the first ENOSPC. Smoke test: `python scripts/check_health.py [--probe]`.
- **Loader Check**: `python scripts/check_loaders.py` (extracts every supported format in /tmp, no vector store needed).
- **Admin Check**: `python scripts/check_admin.py` (upload→ingest→delete smoke test; server must be running).
- **Latency Benchmark**: `python scripts/bench_retrieval.py` (embedding vs FAISS vs Milvus vs LLM). `/chat` responses include `timings` (`retrieval_ms`, `llm_ms`, `llm_calls`, `overhead_ms`, `total_ms`).
- **Tests (offline)**: `pytest -q` runs 751 unit/API/service tests with fake embeddings and a stubbed LLM (no network, ~30s). `pytest --cov=src` for coverage. Lint with `ruff check src tests main.py run_ingestion.py`.
- **Verification (live)**: `python test_agent.py` (requires the API server + a working LLM endpoint).

## Critical Gotchas & Setup
- **CI**: `.github/workflows/ci.yml` runs ruff + pytest on push/PR using `requirements-test.txt` (no torch). Tests must stay network-free; do not add fixtures that call the LLM.
- **Python**: MUST be 3.11. System Python is 3.13/3.14 and has no `torch` wheels. Use conda env `agent-rag` (`~/miniconda3/envs/agent-rag/bin/python`).
- **Install Order**: `pydantic`/`typing-extensions` $\rightarrow$ `torch` $\rightarrow$ `langchain*` $\rightarrow$ app deps (`requirements.txt` lists tested pins; loaders need `python-docx python-pptx openpyxl beautifulsoup4 chardet`). Pin `numpy<2`, `pandas<2.3`, `transformers==4.49.0`, `sentence-transformers==3.4.1`, `huggingface-hub==0.36.0` (torch 2.2.2 breaks with NumPy 2.x ABI; transformers 5.x needs torch>=2.6).
- **Startup**: HF metadata lookups can stall ~10s per launch; `src/__init__.py` caps them with `HF_HUB_ETAG_TIMEOUT=3`. Set `HF_HUB_OFFLINE=1` once the model is cached.
- **LLM Config**: `.env` (gitignored, see `.env.example`) overrides defaults. Current default is free GLM-4-Flash (`https://open.bigmodel.cn/api/paas/v4/`). Local Ollama (`qwen2.5:latest`) works but CPU inference is ~3 tok/s, so cloud is preferred for tests.
- **Retrieval Flow**: `decide_followup` concatenates the previous question only for pronouns or semantically close questions (embedding cosine thresholds), so topic switches are not polluted; `call_model` does deterministic first-stage retrieval (`kb_engine.search(query, state["user_dept"])`) and injects excerpts as a system message; the LLM only formats the answer or triggers `create_support_ticket`.
- **Embeddings**: `EMBEDDING_BACKEND="local"` by default (sentence-transformers + `HF_ENDPOINT=https://hf-mirror.com`). Only chat generation needs `LLM_API_BASE`; ingestion and `scripts/verify_retrieval.py` work offline. `EMBEDDING_BACKEND=fake` gives deterministic vectors for tests (used by CI).
- **Vector Backend**: `src/config.py` `VECTOR_STORE_TYPE` switches `"faiss"` (default, local) vs `"milvus"` (Docker). Same interface in `src/engine.py`.
- **Lazy engine**: `kb_engine` is a proxy; the model loads on first use. Use `get_engine()` when you need the object, and `reset_engine()` in tests. `import src.engine` must stay fast (no model load).
- **Infra**: `docker compose up -d` starts etcd + Milvus only (local storage, no MinIO). Both must be `healthy` and `curl -f localhost:9091/healthz` must pass before setting `VECTOR_STORE_TYPE=milvus`. Default image is `milvusdb/milvus:v2.5.4` (needed for server-side sparse BM25). If the pull fails, configure registry mirrors in **colima** (`~/.colima/default/colima.yaml` → `docker.registry-mirrors`; on this machine `docker.1ms.run` worked) and `colima restart`; or pass `MILVUS_IMAGE=...`. etcd pulls from `quay.io` directly.
- **Data Structure**: Files live under `DATA_DIR` (default `./data`) as `data/{department_name}/**/*`; supported: PDF/DOCX/PPTX/XLSX/CSV/MD/TXT/HTML/JSON. `data/Demo` ships fixtures for every format (regenerate with `scripts/generate_demo_files.py`). Switching FAISS/Milvus or changing chunk metadata requires `python run_ingestion.py --reset`.

## Testing & Verification
- **Permissions**: Always test with at least two different `user_dept` values to verify data isolation.
- **Reranking**: `src/reranker.py` is wired into `kb_engine.search` behind `RERANK_ENABLED` (default off). Uses a Cross-Encoder (`RERANK_MODEL`, 12 candidates); cache the model first, and expect +~200ms (MiniLM) to +seconds (BGE) on CPU.
