# AGENTS.md

## Core Architecture
- **Chat flow**: `src/chat_service.py` owns validation, maintenance gating, answer caching, error classification and metrics for both `/chat` and `/chat/stream`; `main.py` only adapts to HTTP. Request/response models live in `src/schemas.py`.
- **RAG Pipeline**: LangGraph $\rightarrow$ Milvus $\rightarrow$ Cross-Encoder Reranker. Answers return `sources` (`source`+`page`) built from retrieval metadata; excerpts are wrapped in `<document>` tags and treated as untrusted data.
- **Ingestion**: multi-format (`pdf/docx/pptx/xlsx/csv/md/txt/html/json`) via `src/loaders.py`; XLSX/CSV are split into header-repeating row blocks (`XLSX_ROWS_PER_CHUNK`/`CSV_ROWS_PER_CHUNK`, `XLSX_MAX_ROWS`); optional PDF table extraction (`PDF_TABLES_ENABLED`, needs pdfplumber) and OCR (`OCR_ENABLED`, needs pytesseract/pdf2image); keep metadata keys stable or the Milvus schema requires a reset; incremental — chunks carry `dept/source/page|slide|sheet/doc_id/doc_hash/kind/chunk_index`; unchanged files skipped by hash, changed files are written first and old versions deleted afterwards (crash-safe), removed ones pruned.
- **Zero-downtime rebuild**: `--reset` / the admin console build into a shadow index (Milvus: temp collection + alias swap; FAISS: temp dir + `os.replace`). Queries keep hitting the live index; maintenance is only set during the millisecond alias swap. `count()` is the write target, `live_count()` is what queries see.
- **Citations**: answers include `sources` (`source` + `page`/`slide`/`sheet` + `kind` + `snippet` + relative `score`); same-page chunks are merged, and `score` is a rank (1.0 for the top hit), not a cross-engine comparable value.
- **Failure fallback**: when the LLM is unreachable/timeouts *after* retrieval, the graph answers with the top excerpts (`degraded=true`, `degraded_reason=llm_unavailable`); degraded answers are never cached. Toggle with `LLM_FALLBACK_ENABLED`.
- **CORS**: `CORS_ORIGINS` (comma-separated) enables CORS for the public endpoints; the admin API also rejects foreign `Origin` headers.
- **Authentication**: `AUTH_MODE=none` (default, body-supplied identity) or `jwt` (`src/auth.py`; bearer token is the only source of user/depts/groups, body identity ignored, admin claim gates `/admin/api`). Tokens are minted with `scripts/mint_token.py`; a weak secret refuses startup. `GET /admin/api/session` tells the console its auth mode and claims; the admin UI has a login gate for either a bearer token or `ADMIN_TOKEN`. Department/ACL logic sits behind this, so tests can use either mode.
- **Permission Model**: Department-based isolation implemented via Milvus `expr` metadata filtering (`dept == 'dept_name'`, or `dept in [...]` for multi-department users; FAISS filters after retrieval). Optional document-level ACL lives in `src/acl.py` (`ACL_ENABLED`/`ACL_FILE`, user ids or `group:xxx`), applied after retrieval for both backends. `CHAT_API_KEY` optionally gates `/chat` and `/chat/stream`. Department names are validated/escaped in `src/validation.py` before being embedded in the expression; the API returns 400 for invalid values. The department is injected into tools from `AgentState` (`InjectedState`), never supplied by the LLM.
- **State Management**: Handled by LangGraph `AgentState`, tracking `user_id` and `user_dept` per session.

## Developer Commands
All commands assume the conda env `agent-rag` is active (`conda activate agent-rag`).
Container build: `docker build -t agent-rag:dev .` (CPU-only torch, embedding model baked in; build args `PIP_INDEX_URL`/`TORCH_INDEX_URL`/`HF_ENDPOINT` for slow networks). Production stack: `docker compose -f docker-compose.prod.yml up -d --build` (etcd + Milvus + app, app on :8000). The container healthcheck uses `/info` (liveness) so a fresh deployment is healthy before the first ingestion; point load balancers at `/health` (readiness).
`make help` lists shortcuts (`install/data/ingest/run/test/lint/cov/milvus-up/milvus-down/reset-*/doctor/check/eval/clean`); `scripts/doctor.py` checks the environment.
- **Rate limit / deadline**: `RATE_LIMIT_PER_MINUTE` (0 = off, per forwarded IP or user id, 429 + `Retry-After`); `CHAT_TIMEOUT` caps the whole request (504 `timeout`). Error classification lives in `src/errors.py`.
- **History**: `HISTORY_MAX_MESSAGES` (default 20) is what actually reaches the model; older messages are dropped in user/assistant pairs by `chat_service.trim_history`, so long chats never fail validation. The schema's 200-message cap is only an abuse guard.
- **API Server**: `uvicorn main:app --host 0.0.0.0 --port 8000` (chat UI `/ui/`, ingestion console `/admin`, `GET /info` exposes backend/model)
- **Admin Console**: `/admin` — upload/list/delete files and trigger incremental or full ingestion. APIs live under `/admin/api`; loopback-only unless `ADMIN_TOKEN` is set (then send `X-Admin-Token`). Ingestion runs in a background thread; jobs persist to `logs/ingest_jobs.json` and admin actions are audited in `logs/admin_audit.log` (`GET /admin/api/audit`). Uploads are capped per file and per request (`MAX_UPLOAD_TOTAL_MB`).
- **Data Ingestion**: `python run_ingestion.py` (Must be run before API to populate the vector store).
- **LLM Check**: `python scripts/check_llm.py` (probes `/models` + one chat completion before starting the API).
- **Offline Retrieval Check**: `python scripts/verify_retrieval.py` (no LLM needed; asserts dept isolation).
- **Retrieval Eval**: `VECTOR_STORE_TYPE=faiss python scripts/eval_retrieval.py` (hit@k, MRR, leakage from `eval/cases.jsonl`; run for both backends after ingestion). Hybrid retrieval is on by default; compare with `HYBRID_ENABLED=false`.
- **Hybrid Retrieval**: `HYBRID_ENGINE=auto` (default) uses Milvus server-side sparse BM25 when the server is >= 2.5 and the collection has a `sparse` field with a BM25 index; otherwise it falls back to in-process BM25 (`src/lexical.py`, per-department, RRF-fused, warmed in a background thread). `local` forces in-process; `milvus` fails loudly if unsupported. Check `GET /info` → `hybrid.engine`. Unit checks: `python scripts/check_hybrid.py`; server-side end-to-end: `VECTOR_STORE_TYPE=milvus python scripts/check_hybrid_milvus.py` (skips below 2.5, uses a throwaway collection).
- **Metrics**: `GET /metrics` (Prometheus). Optional `METRICS_TOKEN` requires `Authorization: Bearer ...`. Per-process counters; do not expose publicly. `agent_rag_retrieval_engine_total{engine}` shows whether vector/local/milvus/fallback served each query.
- **Hashing / summaries**: file digests go through `src/hashing.py` (cached by `path+mtime+size`); admin listing uses `kb_engine.doc_summary()` (cached for 5s and invalidated on writes), never per-file queries.
- **Caching**: `src/cache.py` is an LRU+TTL FAQ cache keyed by `dept + normalised question`; only single-turn answers with exactly one LLM call are stored, and every KB write clears it. `src/embedding_cache.py` memoises `embed_query` (ingestion embeddings are not cached). Bypass with `Cache-Control: no-cache`. `/health` → `cache`, metrics `agent_rag_cache_total{cache,result}`.
- **Health Check**: `GET /health` (vector store chunks, ingestion job, maintenance; `?probe=1` also pings the LLM). `down` → HTTP 503 when the index is empty/unreachable; `degraded` → 200 during ingestion/rebuild. Smoke test: `python scripts/check_health.py [--probe]`.
- **Loader Check**: `python scripts/check_loaders.py` (extracts every supported format in /tmp, no vector store needed).
- **Admin Check**: `python scripts/check_admin.py` (upload→ingest→delete smoke test; server must be running).
- **Latency Benchmark**: `python scripts/bench_retrieval.py` (embedding vs FAISS vs Milvus vs LLM). `/chat` responses include `timings` (`retrieval_ms`, `llm_ms`, `llm_calls`, `overhead_ms`, `total_ms`).
- **Tests (offline)**: `pytest -q` runs 309 unit/API/service tests with fake embeddings and a stubbed LLM (no network, ~25s, 92% coverage). `pytest --cov=src` for coverage. Lint with `ruff check src tests main.py run_ingestion.py`.
- **Verification (live)**: `python test_agent.py` (requires the API server + a working LLM endpoint).

## Critical Gotchas & Setup
- **CI**: `.github/workflows/ci.yml` runs ruff + pytest on push/PR using `requirements-test.txt` (no torch). Tests must stay network-free; do not add fixtures that call the LLM.
- **Python**: MUST be 3.11. System Python is 3.13/3.14 and has no `torch` wheels. Use conda env `agent-rag` (`~/miniconda3/envs/agent-rag/bin/python`).
- **Install Order**: `pydantic`/`typing-extensions` $\rightarrow$ `torch` $\rightarrow$ `langchain*` $\rightarrow$ app deps (`requirements.txt` lists tested pins; loaders need `python-docx python-pptx openpyxl beautifulsoup4 chardet`). Pin `numpy<2`, `pandas<2.3`, `transformers==4.49.0`, `sentence-transformers==3.4.1`, `huggingface-hub==0.36.0` (torch 2.2.2 breaks with NumPy 2.x ABI; transformers 5.x needs torch>=2.6).
- **Startup**: HF metadata lookups can stall ~10s per launch; `src/__init__.py` caps them with `HF_HUB_ETAG_TIMEOUT=3`. Set `HF_HUB_OFFLINE=1` once the model is cached.
- **LLM Config**: `.env` (gitignored, see `.env.example`) overrides defaults. Current default is free GLM-4-Flash (`https://open.bigmodel.cn/api/paas/v4/`). Local Ollama (`qwen2.5:latest`) works but CPU inference is ~3 tok/s, so cloud is preferred for tests.
- **Retrieval Flow**: `decide_followup` concatenates the previous question only for pronouns or semantically close questions (embedding cosine thresholds), so topic switches are not polluted; `call_model` does deterministic first-stage retrieval (`kb_engine.search(query, state["user_dept"])`) and injects excerpts as a system message; the LLM only formats the answer or triggers `create_support_ticket`.
- **Embeddings**: `EMBEDDING_BACKEND="local"` by default (sentence-transformers + `HF_ENDPOINT=https://hf-mirror.com`). Only chat generation needs `LLM_API_BASE`; ingestion and `scripts/verify_retrieval.py` work offline. `EMBEDDING_BACKEND=fake` gives deterministic vectors for tests (used by CI).
- **Vector Backend**: `src/config.py` `VECTOR_STORE_TYPE` switches `"faiss"` (default, local) vs `"milvus"` (Docker). Same interface in `src/engine.py`.
- **Lazy engine**: `kb_engine` is a proxy; the model loads on first use. Use `get_engine()` when you need the object, and `reset_engine()` in tests. `import src.engine` must stay fast (no model load).
- **Infra**: `docker compose up -d` starts etcd + Milvus only (local storage, no MinIO). Both must be `healthy` and `curl -f localhost:9091/healthz` must pass before setting `VECTOR_STORE_TYPE=milvus`. Default image is `milvusdb/milvus:v2.5.4` (needed for server-side sparse BM25). If the pull fails, configure registry mirrors in **colima** (`~/.colima/default/colima.yaml` → `docker.registry-mirrors`; on this machine `docker.1ms.run` worked) and `colima restart`; or pass `MILVUS_IMAGE=...`. etcd pulls from `quay.io` directly.
- **Data Structure**: Files live under `DATA_DIR` (default `./data`) as `data/{department_name}/**/*`; supported: PDF/DOCX/PPTX/XLSX/CSV/MD/TXT/HTML/JSON. `data/Demo` ships fixtures for every format (regenerate with `scripts/generate_demo_files.py`). Switching FAISS/Milvus or changing chunk metadata requires `python run_ingestion.py --reset`.

## Testing & Verification
- **Permissions**: Always test with at least two different `user_dept` values to verify data isolation.
- **Reranking**: `src/reranker.py` is wired into `kb_engine.search` behind `RERANK_ENABLED` (default off). Uses a Cross-Encoder (`RERANK_MODEL`, 12 candidates); cache the model first, and expect +~200ms (MiniLM) to +seconds (BGE) on CPU.
